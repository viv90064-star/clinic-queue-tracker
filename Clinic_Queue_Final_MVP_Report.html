Summary of What the Live Application Does

The Clinic Queue Tracking System is a lightweight, mobile-first web application designed to eliminate waiting-time uncertainty for outpatient clinic patients.

  • Patient Queue Lookup: Patients visiting the clinic register at the physical front desk and receive a paper slip with their token number (e.g. 021, 022, 023, 024, 025). They open the mobile website, type their token number or tap the demo shortcut, and click Check Queue.
  • Real-Time Status & Wait Estimation: The application queries the central queue state to display the patient's token, status (Waiting, Now Being Called), the exact count of patients ahead in line, an approximate waiting-time range (e.g. 20–30 minutes calculated at ~5–7.5 minutes per consultation), and an interactive 5-segment visual progress bar.
  • Turn Approaching Alert: When a patient is next in line or being called, an automatic high-visibility notification alerts the patient to move to Consultation Room 1.
  • Protected Receptionist Controls: Staff sign in with clinic credentials to view the current token with the doctor, next token in line, total waiting patients, and a live queue table. Clicking Call Patient automatically updates the queue across all devices instantly without needing page reloads.
Zero Patient Data Exposure: The application does not collect, store, or display sensitive personal health information (PHI), phone numbers, or patient names. It operates strictly on anonymous sequential token identifiers.

Product Brief & MVP Scope

1. Project Context & Problem Statement

The selected healthcare problem is that patients visiting busy outpatient clinics in Patna, Bihar face acute uncertainty about their queue position and expected waiting duration after completing registration. Because OPD consultation times vary and clinics lack digital queue monitors, patients constantly experience anxiety, crowd the narrow corridors near doctor rooms, and repeatedly interrupt reception staff to ask: "When will my turn come?"

2. Target Users

Primary Users: Registered outpatient clinic patients and accompanying family caregivers who want to track queue progress on their personal mobile phones while waiting nearby.
Secondary Users: Clinic front-desk receptionists who need a simple, single-click interface to call the next patient and keep queue progress synchronized.

3. One-Line MVP Scope Statement

"A simple web page where a registered patient enters a token number to see their queue position and an approximate waiting-time range, kept up to date through a basic reception dashboard."

4. Seven-Step Patient User Journey

5. Mathematical Algorithm for Wait-Time & Position Calculation

The calculation engine in js/queue-service.js uses a deterministic formula modeling real clinic consultation pacing (~5 to 7.5 minutes per patient):

1. Patients Ahead Calculation:
Patients Ahead (N) = Waiting Tokens Ahead + (1 if doctor actively seeing a patient, else 0)

2. Waiting-Time Bracket Calculation:
• If $N = 0$ and status is Calling: "Now (Your Turn!)"
• If $N = 0$ and status is Waiting: "Next in line (< 5 mins)"
• If $N = 1$: "5–10 minutes"
• If $N = 2$: "10–15 minutes"
• If $N = 3$: "15–20 minutes"
• If $N \ge 4$: Min = N × 5 mins, Max = Round(N × 7.5 / 5) × 5 mins $\rightarrow$ "20–30 minutes" for Token 025.

3. Visual Progress Bar Segments (5 Steps):
Step 1 (Registered) $\rightarrow$ Step 2 ($N \le 3$) $\rightarrow$ Step 3 ($N \le 2$) $\rightarrow$ Step 4 ($N \le 1$, Turn Approaching) $\rightarrow$ Step 5 (Calling / In Consultation).

6. Security Rules Specification (firestore.rules)

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    // Patients can read queue metrics without signing in
    match /metadata/{document=**} {
      allow read: if true;
      allow write: if request.auth != null; // Only authenticated clinic staff can write
    }
    match /tokens/{tokenId} {
      allow read: if true;
      allow write: if request.auth != null; // Only authenticated clinic staff can advance queue
    }
  }
}

2. Short Conclusion

The Clinic Queue Tracking System MVP successfully demonstrates how a focused, lightweight web application can solve patient waiting-time uncertainty in busy outpatient clinics. By respecting strict MoSCoW MVP boundaries—avoiding unnecessary self-registration or online payment systems—the product delivers immediate value to patients through clear queue positions and transparent waiting estimates. Reception staff retain full operational control through a single-click interface protected by cloud authentication and security rules. The system was verified across mobile and desktop devices and successfully deployed to Google Cloud Firebase Hosting on the free tier.

3. Future Improvements Roadmap (Post-MVP Extensions)

  • Multi-Doctor / Multi-Room Support: Expand the database schema to support concurrent queues across distinct OPD specialty rooms (e.g. Pediatrics in Room 1, Orthopedics in Room 2).
  • Automated SMS / WhatsApp Queue Alerts: Integrate a cloud-triggered notification channel to ping patients when they reach 2 patients ahead, allowing them to leave the clinic grounds safely.
  • Doctor Delay Status Indicator: Provide a toggle for reception staff to broadcast doctor emergency delays (e.g. "Doctor delayed by 20 mins due to emergency round").
  • Physical Registration Slip QR Codes: Print a scannable QR code on physical clinic slips that opens the patient's queue status directly without entering any digits.
